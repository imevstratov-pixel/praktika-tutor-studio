# Демо с реальным ИИ

React-интерфейс и `/api/*` работают на одном адресе. Worker использует общий модуль `local/analysis.mjs`: те же ограничения ввода, строгую схему, проверку цитат и ссылок. Полный диалог тьютора в этой версии не реализован: сервис готовит материалы для него.

Модель — Gemini 2.5 Flash через Polza AI. Единственный секрет окружения — `TUTOR_API_KEY`; его нужно задать на сервере. Адрес API и модель зафиксированы в Worker, клиент не может их подменить. Не включайте `.env.polza.local` в исходники или архив размещения.

Общий лимит демо — 20 попыток. D1-binding `DB` хранит только счётчик и временную блокировку, без текстов и результатов. Лимит действует между браузерами и экземплярами сервера; один запрос обрабатывается за раз. Ошибки и отмены после резервирования тоже расходуют попытку, потому что провайдер может уже списать стоимость. Статус показывает оставшиеся попытки. Отсутствие базы или ключа закрывает доступ к генерации.

Для размещения создайте `.openai/hosting.json` с фактическим `project_id`, `"d1":"DB"`, `"r2":null`, без `static`. Миграция `migrations/0000_demo_budget.sql` должна примениться до запуска; создание таблиц во время запросов не выполняется. После обычной сборки из `ui` выполните `node hosted/build.mjs` из корня проекта. Сборщик добавит в размещаемую версию явную метку API и создаст `dist/server/index.js`. Обычная сборка GitHub Pages остаётся без метки и не обращается к API.

Проверки Worker используют настоящую SQLite-базу и подменяют только внешнего провайдера. Запуск: `node --test hosted/worker.test.mjs`. Они включены в общую приёмку `npm run accept` из `ui`. Приёмка требует два полных зелёных прогона подряд. Проверку опубликованной демки с реальным провайдером проводите отдельно и учитывайте расход попытки.

Демо создаёт черновик. Дословность цитаты не доказывает точность смысловой связи. Перед передачей материалов тьютору методист должен проверить определения, направления и условия отношений, а также полноту исходного учебного контекста.
