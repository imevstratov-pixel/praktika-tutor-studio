# Локальная студия с языковой моделью

Требуется Node.js 20 или новее. Распакуйте проект целиком, сохранив соседние папки `dist/` и `local/`. На macOS дважды нажмите `local/start.command`. На любой ОС из папки проекта выполните `node local/server.mjs` и откройте http://127.0.0.1:4187. Сервер доступен только на этом компьютере. Чтобы завершить работу, нажмите Ctrl+C в терминале.

Если проект получен через `git clone`, папки `dist/` ещё нет. Сначала установите Node.js 24 и выполните из `ui/` команды `npm ci` и `npm run build:local`. После этого вернитесь в корень проекта и запустите сервер. GitHub Pages размещает браузерную версию; этот локальный сервер на Pages не работает.

## Ollama на компьютере методиста

Запустите Ollama и установите поддерживающую чат модель с достаточным контекстом и поддержкой русского языка. Команда `ollama list` показывает установленные модели. По умолчанию студия проверяет локальную Ollama на порту 11434 и выбирает первую доступную модель, исключая модели с признаками облачных моделей и эмбеддингов. Для воспроизводимых результатов укажите точное имя установленной модели:

```sh
TUTOR_MODEL='имя-модели-из-ollama-list' node local/server.mjs --open
```

Для длинных материалов подберите достаточно большой контекст модели. Одно обращение включает входной текст, инструкцию и генерируемый JSON. Студия принимает до 32 000 знаков и ждёт ответ до трёх минут. Для первой пробы возьмите 2–4 содержательных абзаца. При отсутствии модели браузерный режим остаётся доступен. [Документация локального API Ollama](https://docs.ollama.com/api/openai-compatibility)

## Совместимый сервер

Администратор может задать адрес сервиса с поддержкой `POST /v1/chat/completions`, JSON mode через `response_format`, `max_tokens` и ответом в `choices[0].message.content`. В интерфейсе будет отображаться имя хоста и модели. В режиме `compatible` статус означает, что конфигурация задана. Доступность модели и ключ проверяются при первом запросе.

```sh
export TUTOR_PROVIDER=compatible
export TUTOR_API_BASE='https://your-inference-server.example/v1'
export TUTOR_MODEL='your-model-id'
# Если требуется авторизация, передайте TUTOR_API_KEY через менеджер секретов.
node local/server.mjs --open
```

Для локального совместимого сервиса можно указать HTTP на `127.0.0.1` или `localhost`. Для внешнего адреса требуется HTTPS. Ключ задаётся только на сервере. В этом режиме обработчик отправляет название и текст выбранному сервису после запуска ИИ-разбора. Условия хранения на стороне провайдера определяет администратор. Сервер студии не создаёт файлов и журналов с учебным материалом и не передаёт ключ в браузер.

Дополнительные настройки: `TUTOR_PORT` меняет порт студии, `TUTOR_API_BASE` в режиме Ollama меняет адрес её локального API, `TUTOR_PROVIDER=off` отключает поиск модели. Неизвестное значение провайдера останавливает запуск.

## Polza AI

Для локальной студии можно использовать Gemini 2.5 Flash через Polza AI. В корне проекта создайте файл `.env.polza.local` с доступом только для владельца (`chmod 600 .env.polza.local`):

```dotenv
TUTOR_PROVIDER=compatible
TUTOR_API_BASE=https://polza.ai/api/v1
TUTOR_MODEL=google/gemini-2.5-flash
TUTOR_JSON_MODE=schema
TUTOR_PORT=4189
TUTOR_API_KEY=ваш_ключ
```

Этот файл исключён из Git. Ключ не должен попадать в исходники, отчёты, браузерную сборку или GitHub Pages. Для запуска на macOS откройте `local/start-polza.command`; из терминала в корне проекта выполните:

```sh
node --env-file=.env.polza.local local/server.mjs
```

Студия доступна по адресу http://127.0.0.1:4189. После нажатия «Подготовить содержание» сервер отправляет лекцию модели. Режим `schema` передаёт провайдеру строгую структуру ответа; затем сервер независимо проверяет цитаты и ссылки. Для других совместимых провайдеров по умолчанию сохраняется режим `object`; используйте `schema` только при поддержке `response_format.json_schema`. Синтаксическая проверка не заменяет проверку смысла методистом.

Формат подтверждён [примером Polza с Gemini 2.5 Flash](https://polza.ai/use-cases/protokoly-vstrech) и [документацией структурированных ответов](https://polza.ai/docs/gaidy/structured-output). Публичная версия на GitHub Pages по-прежнему работает без серверного ключа; для общей онлайн-версии с моделью понадобится отдельный сервер.

## Проверка и границы

`GET /api/status` возвращает поля `ai` и `provider`. `POST /api/structure` принимает JSON `{"title":"…","text":"…"}` со страницы того же локального сервера. На один запрос сервер нумерует исходные фрагменты, передаёт их модели как данные и требует дословную цитату для каждой темы, каждого термина и каждой связи. Сервер проверяет присутствие цитат в нужных фрагментах, уникальность узлов, существование ссылок, размеры входа и выхода. Он возвращает исходные фрагменты, темы, словарь и связи. Интерфейс собирает промпты по отредактированной методистом структуре. Наличие цитаты подтверждает её происхождение; точность смыслового вывода проверяет методист.

При ошибке модели API возвращает HTTP-ошибку и русское сообщение в `error`. Для диагностики проверьте длину текста, доступность модели и корректность имени. Запуск встроенных проверок контракта на временном локальном тестовом сервисе:

```sh
node --test local/server.test.mjs
```

Проверки не требуют установки пакетов или настоящего ключа. Для проверки подключения к реальной модели запустите студию с вашей конфигурацией и обработайте короткий фрагмент, где есть явное определение. Например: «В этом курсе участником проекта называют человека или организацию, выполняющую согласованную роль в проекте. Ответственный участник следит за выполнением своей задачи». Откройте источник получившегося термина и сравните определение с текстом.
