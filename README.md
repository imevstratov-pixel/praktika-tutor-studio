# Практика

Подготовка материалов для корпоративного ИИ-тьютора после лекции: текст → проверка тем и словаря → граф знаний и инструкции для тьютора.

[Демо с ИИ](https://praktika-tutor-studio-shmk.aquaticthistle1.chatgpt.site) · [Автономный пример на GitHub Pages](https://imevstratov-pixel.github.io/praktika-tutor-studio/)

## Что можно сделать

- Вставить текст лекции, загрузить TXT/MD или попробовать учебный пример.
- Проверить темы, исправить определения и сохранить обязательные термины.
- Исследовать граф: выбрать узел, увидеть его связи, определение и дословные опорные фрагменты лекции.
- Скопировать текст инструкции и JSON с данными курса; скачать полный пакет занятия и описание.

Демо с ИИ отправляет текст лекции в Gemini 2.5 Flash через Polza AI. Ключ хранится на сервере; общий лимит — 20 попыток на всех посетителей. Полученный материал — черновик для проверки методистом. Полный диалог с тьютором в этой версии не реализован. Устройство размещённой версии описано в [руководстве](hosted/README.md).

Версия на GitHub Pages работает целиком в браузере и разбирает текст по правилам, без отправки в модель. В обеих версиях черновик сохраняется на устройстве посетителя. Учебные примеры содержат вымышленные ситуации и числа, а первый вопрос сформирован по шаблону.

## Запуск из исходников

Нужен Node.js 24 и npm.

```sh
git clone https://github.com/imevstratov-pixel/praktika-tutor-studio.git
cd praktika-tutor-studio/ui
npm ci
npm run dev
```

Страница разработки: <http://127.0.0.1:4188>.

Собрать автономный HTML и запустить локальную студию:

```sh
npm run build:local
cd ..
node local/server.mjs
```

Откройте <http://127.0.0.1:4187>. Настройка Ollama и совместимого сервиса описана в [руководстве локального сервера](local/README.md). Ключи задаются на сервере; GitHub Pages серверную часть не запускает.

## Проверки и публикация

Из папки `ui`:

```sh
npm run browser:install
npm run smoke
npm run accept
```

Приёмка требует два полных зелёных прогона подряд на неизменных исходниках, тестах и сборке, без пропусков и повторных попыток. Проверяются данные, сервер, поведение интерфейса, граф, цитаты, копирование и скачиваемые файлы. Подробнее: [правило приёмки](QUALITY.txt).

GitHub Actions выполняет приёмку для изменений проекта. Успешная проверка ветки `main` публикует ту же проверенную сборку в GitHub Pages. Отчёты сохраняются в артефактах запуска. Для pull request выполняются проверки без публикации.

После публикации сайт можно проверить отдельно:

```sh
node scripts/verify-published.mjs https://imevstratov-pixel.github.io/praktika-tutor-studio/
```

Скрипт запускается из `ui`, использует отдельный браузер и вымышленную лекцию. Он сравнивает опубликованный HTML с `dist/index.html`. При проверке сборки из GitHub Actions укажите её принятый `index.html` через `--artifact /путь/к/index.html`. Проверка копирования использует подмену буфера внутри теста и не меняет системный буфер обмена.

## Состав проекта

- `ui/src` — интерфейс, разбор текста, граф и копирование.
- `ui/tests` — проверки данных и браузерные сценарии.
- `ui/scripts` — сборка, приёмка и проверка опубликованного сайта.
- `local` — необязательный сервер для подключения модели.
- `hosted` — сервер демо с ИИ, общим лимитом и миграцией базы.
- `.github/workflows` — проверка и публикация.

Используются Fluid Functionalism и shadcn/ui. Происхождение компонентов: [COMPONENTS.txt](ui/COMPONENTS.txt). Лицензии сторонних компонентов: [THIRD_PARTY_NOTICES.txt](ui/THIRD_PARTY_NOTICES.txt).
